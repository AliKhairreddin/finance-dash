# September 9 PDF claim validation

Reviewed `9 sep finance-summary-en-for-ali.pdf` against current source, read-only stored data, and the running UI. The PDF's proposed changes were treated as claims to investigate, not instructions to execute. No financial records, invoices, allocations, bank credentials, or provider assignments were changed for this audit.

| Finding | Validation and action |
| --- | --- |
| F01: Unending analytics/bank totals | Confirmed. The analytics endpoint required complete history from every source before calculating stored records, while the client retried indefinitely. Wise had missing coverage even when Revolut was complete. Calculations now run independently of history backfill, return source coverage, disclose partial totals, preserve previous calculations during refresh, and time out with a retry action after 45 seconds. Local development snapshots explicitly report unverified coverage. |
| F02: Date control covers bank view buttons | Reproduced at 841 px: the centers of Group, Card, and Account hit the date label. Toolbar wrapping fixes the collision. All three hit targets passed at 390, 759, 841, 1024, and 1440 px. |
| F03: Manual-invoice keyboard escape | Reproduced background focus and non-working Escape. Reused the shared Base UI dialog. Forty-five forward/reverse Tab steps stayed inside; Escape closed it and restored focus to Add invoice. |
| F04: “Exact match” with a $25 difference | Confirmed invoice 2026/1349 at $1,585.50 and its linked Revolut receipt at $1,560.50. The stored match reason explicitly applied a $100 tolerance and recorded the $25 difference. Display now says “Tolerance match” and shows the recorded difference. A bank fee is **not verified**; invoice and allocation amounts remain unchanged. Invoices 2026/1352 and 2026/1353 were already paid through manual allocations and were left unchanged. |
| F05: Revenue variance sign | Confirmed a label error. The calculation consistently uses Dashboard minus RedTrack, producing -$46,712.62 for the cited values. Corrected that formula label; revenue and variance values remain unchanged. |
| F06: Supplier-bill error off-screen | Confirmed. A rejected submission now announces, focuses, and scrolls to the error summary, including repeated rejected submits. At 390 px the focused error was visible between y=94 and y=162 after Save. |
| F07: Position mislabeled as Profit | Confirmed from the cash/receivables/payables calculation. Renamed the calculated metric to “Net operating position” in the view and PNG export. Financial formulas and the separate user-entered Profit growth field remain unchanged. |
| F08: Negative distribution appears positive | Confirmed. The cited -€91,105.84 now renders with the negative color; zero is neutral. The selector says “Currency ledger,” and converted headline totals say “USD estimate.” |
| F09: Provider grouping omits unassigned spend | Confirmed exactly for September 8: $23,092.80 assigned plus $22,293.28 unassigned equals $45,386.08 reported spend. Added the unassigned group, its drilldown (57 accounts), and shown/total spend. All 122 account-day rows reconcile without changing assignments. |
| F10: Provider form preselects supplier | Confirmed in source and UI. A fresh form now shows “Choose supplier,” with Save disabled until an explicit selection. No provider was created during testing. |
| F11: Mobile readability/density | Confirmed concrete overflow and wrapping defects. Reflowed invoice, expense, and unified-bank transaction rows at mobile widths so amounts/status/actions are reachable without horizontal scrolling; retained columns and sorting. Compact invoice/expense summaries and nonshrinking count badges address the reproduced cases. Broad Documents/Management redesign suggestions were not treated as established functional defects. |
| F12: June/July reporting discrepancy | Confirmed for the nonzero platform YTD rows: their revenue, spend, and profit reconcile to January–July monthly records, consistent with report coverage through July 31. Display uses the uniquely reconciled effective period and retains the original label in an information control. Ambiguous zero-only BIGO + SC data keeps its original label. No source workbook or numerical data was rewritten. Every platform column now has accessible ascending/descending sorting and URL state. |
| F13: Connection recovery | Confirmed the missing recovery destination and ambiguous count label. Moved Connections first in Settings, labeled the count as configuration fields, added the Wise statement-import destination and administrator guidance. This does not repair missing credentials or establish that Wise API access is restored. |
| F14: Navigation consolidation | Not established as a defect. The proposed five-area redesign is a preference; existing navigation remains in place. |

Validation used a local Worker preview reading the current showcase Convex data. Persistent mutations were blocked; analytics job progress was held in memory. Integration credentials were not loaded into the preview, so its configuration badges are not proof of deployed connection readiness. Source checks and the previously stored connection issue supported the recovery change.

The combined release passed TypeScript checks, all 474 automated tests, and the production build. Targeted regressions cover partial/empty/error/cancelled/timed-out analytics, independent bank coverage, exact/tolerance payment labels, unassigned grouping, and uniquely reconciled reporting periods. Browser checks covered the cited toolbar widths, invoice keyboard behavior, supplier validation, provider defaults and drilldown, negative distribution, platform sorting, and mobile list layout. This is not a full cross-browser, zoom, screen-reader, or accounting audit.

The same release includes the separately requested Slash virtual-account filter, verified by its contributing task across Group, Card, Transactions, reloads, and filter removal. That feature was not inferred from the PDF.
